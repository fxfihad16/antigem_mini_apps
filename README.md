# Agent Hina mini apps

Mini apps for [Agent Hina](https://github.com/fxfihad16/AgentHina): small HTML/CSS/JS apps that run inside Agent Hina like
real Android apps (their own icon and Recents card, native storage, files, network, notifications…). Agent Hina's
**Mini Apps → Get apps** screen lists the apps of this repository and installs or updates them like an app store.

| App | What it is |
| --- | --- |
| [Showcase](apps/showcase/) | A tour of the mini app SDK: storage, files, network, notifications, background tasks, threads |
| [Habits](apps/habits/) | Daily habit tracker with streaks, a 4-week history and a daily reminder |
| [Pocket Notes](apps/notes/) | Markdown notes with pins, reminders, search, sharing and export |
| [Sky](apps/weather/) | Weather forecast with an hourly chart, 7 days and rain alerts in the background |
| [Gallery](apps/gallery/) | Photos and videos on the phone, with the native viewer |
| [Focus](apps/focus/) | Pomodoro timer with a live countdown notification (Pause / Skip buttons) |
| [Dev Toolbox](apps/devtools/) | HTTP client, WebSocket tester, encoders and hashes, and Agent Hina's MCP tools |
| [Explorer](apps/explorer/) | Wikipedia, dictionary, currency rates, countries and Hacker News, from free APIs |

## Layout

```
apps/<folder>/            an app: manifest.json, index.html, icon.png, …  (the source; edit these)
dist/<id>-<version>.agapp the signed packages Agent Hina downloads            (generated by publish)
hina-mini-apps.json    the catalog Agent Hina reads                        (generated by publish)
tools/agapp.mjs           packages, signs and publishes (Node 18+, no dependencies)
```

Agent Hina reads `https://raw.githubusercontent.com/fxfihad16/antigem_mini_apps/HEAD/hina-mini-apps.json` and
the files it points to, so `dist/` and the catalog must be committed.

## Why packages are signed

Agent Hina only installs signed packages, like Android with APKs: the first install remembers the developer's key, and an
update must be signed with the same key and have a higher version. Every file of an installed app is checked against
the signature when it loads. The catalog also lists each package's sha256 and the key's fingerprint; Agent Hina refuses a
download that doesn't match.

## One-time setup: your developer key

Use the same key for every release, forever. If you lose it, the published apps can never be updated.

- **Key from the phone** (recommended): in Agent Hina, Mini Apps → key icon → Create, then **Back up**. The backup
  (`Download/Agent Hina/hina-key-….agkey`, locked with your password) is what you use here: copy it to your computer.
- **Or a new key on a computer**: `node tools/agapp.mjs keygen --developer "Your Name" --out ~/hina.agkey`
  (then Mini Apps → key icon → Import on the phone, to sign there too).

Keep the `.agkey` outside this repository (`*.agkey` is ignored by git) and keep a second copy somewhere safe.

## Publishing

1. Change an app in `apps/<folder>/` and raise `"version"` in its `manifest.json` (e.g. 1.0.0 → 1.0.1). A changed app
   with the same version is refused: phones only update to a higher version.
2. Sign and write the catalog:
   ```bash
   node tools/agapp.mjs publish --key ~/hina.agkey      # asks for the password (or set AGAPP_PASSWORD)
   ```
   Only changed apps are signed again; old packages are removed from `dist/`.
3. Commit `apps/`, `dist/` and `hina-mini-apps.json`, and push. Agent Hina shows the new version within a few minutes
   (GitHub caches raw files briefly).

**Or let GitHub sign them**: add the repository secrets `AGAPP_KEY` (the whole `.agkey` file's text) and
`AGAPP_PASSWORD`. Then pushing a change under `apps/` runs [publish.yml](.github/workflows/publish.yml), which signs
and commits `dist/` and the catalog. The key is stored encrypted by GitHub; anyone who can change the workflow can use it.

## Adding an app

1. Make the app (an Agent Hina agent with the Mini App Developer MCP can build and test it on the phone, then copy the
   folder from `~/mini-apps/<folder>`). Give it a unique reverse-domain `id` (`com.yourname.app`) that you never change.
2. Copy its folder to `apps/<folder>/`, with a square `icon.png` (192 px or more).
3. Publish as above.

A development copy with the same id in a phone's `~/mini-apps` blocks installing the published one (it would get that
app's data); the Get apps screen offers to remove it.

## Catalog format

```json
{
  "name": "Agent Hina mini apps",
  "format": 1,
  "generated": "2026-11-12T10:00:00.000Z",
  "apps": [
    {
      "path": "apps/habits",
      "id": "io.hina.habits",
      "name": "Habits",
      "version": "1.0.1",
      "version_code": 1000001,
      "description": "Daily habit tracker",
      "icon": "apps/habits/icon.png",
      "package": "dist/io.hina.habits-1.0.1.agapp",
      "sha256": "<sha256 of the .agapp>",
      "size": 15754,
      "developer": "Your Name",
      "fingerprint": "<sha256 of the signing key's public key>",
      "permissions": { "notifications": true },
      "updated": "2026-11-12T10:00:00.000Z"
    }
  ]
}
```

`icon` and `package` are relative to the catalog (absolute https URLs work too). `tools/agapp.mjs` is a copy of
Agent Hina's (`~/mini-apps/tools/agapp.mjs` on the phone): refresh it when Agent Hina updates it.
